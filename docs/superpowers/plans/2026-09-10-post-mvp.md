# Personal Work OS — Post-MVP Plan

> Continues from `2026-09-09-mvp-foundation.md`. Same constraints: TypeScript strict, no `any`,
> layering route → service → repository → Drizzle, design tokens only, Zod validation, every screen
> handles loading/empty/error, one-line commits, no AI features.

**Goal:** Close the four post-MVP gaps recorded in `progress.md` — account recovery, manual task
order, a findable project archive, and a week view on the calendar — and hand Deva a written
procedure for moving off the local Supabase stack onto a hosted project.

**Decisions taken with Deva (2026-09-10):**

- Task reordering uses native HTML5 drag-and-drop with visible ▲▼ buttons as the keyboard and touch
  fallback, plus a Smart/Manual sort toggle so a manual order actually survives.
- Both password reset **and** magic-link sign-in are built; they share `/auth/callback`.
- The archive is its own page at `/projects/archive`, not just a filter.

---

### Task 1: Account recovery (password reset + magic link)

No migration — Supabase Auth owns this.

- `auth.schema.ts`: `emailOnlySchema` (forgot password, magic link), `newPasswordSchema`
  (password ≥ 8 + confirmation match).
- `auth.service.ts`: `sendPasswordReset`, `sendMagicLink`, `updatePassword`. Reuse
  `friendlyAuthMessage`; add patterns for "same password" and "expired".
- `/auth/callback`: accept `type=recovery` and forward to `/reset-password`.
- `hooks.server.ts`: exempt `/(auth)/reset-password` from the "signed in → go home" redirect; the
  recovery link signs the user in before they choose a new password.
- Routes: `(auth)/forgot-password`, `(auth)/reset-password`; magic-link action on the login page.
- Tested: `friendlyAuthMessage` mapping, `newPasswordSchema` mismatch rule.

### Task 2: Manual task order (tested: move/reorder)

No migration — `tasks.sort_order` already exists.

- `task.utils.ts`: pure `moveTaskInList(ids, taskId, toIndex)` returning the reordered id list, and
  `sortOrderPatches(ids)` mapping ids to their new `sortOrder`. Both test-first.
- `sortTasks` gains a `mode: 'smart' | 'manual'`; manual sorts by `sortOrder` then `createdAt` and
  still trails done tasks.
- `task.repository.ts`: `updateTaskOrder(userId, patches)` in one transaction.
- `task.service.ts`: `reorderTask(userId, projectId, taskId, toIndex)` — reorders within the task's
  own milestone group, writes patches, logs activity.
- Project page: `?sort=manual` toggle, `moveTask` action, drag handles + ▲▼ buttons in `TaskRow`.

### Task 3: Project archive page

No migration — `archived` is an existing project status.

- `project.repository.ts` / `project.service.ts`: `listArchivedProjects(userId)` returning
  completed + archived projects with company context.
- Route `(app)/projects/archive`: grouped by company, with `restore` (→ `paused`) and
  `archive` actions reusing `statusTransitionPatch`.
- Projects page header links "Archived (n)".

### Task 4: Calendar week view (tested: grid)

- `calendar-grid.ts`: `buildWeekGrid(weekStart, today)`, `shiftWeek`, `weekLabel`, `currentWeek`.
  Test-first, mirroring the month-grid tests.
- `calendar.utils.ts`: `splitDayItems` separating timed from all-day items.
- Route `/calendar?view=week&week=YYYY-MM-DD`; `WeekGrid.svelte` beside `MonthGrid.svelte`.
- Month/week toggle preserves the visible date when switching.

### Task 5: Hosted Supabase runbook (documentation)

`docs/supabase-production-setup.md` — the manual steps Deva must perform: create the project, copy
the pooled connection string and anon key, fill `.env`, run `bun run db:migrate`, set
`site_url`/redirect URLs, turn email confirmation on, then a verification checklist.

- `progress.md`: MVP recorded as merged; this milestone's tasks tracked.
